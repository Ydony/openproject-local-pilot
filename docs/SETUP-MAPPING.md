Source tag read: `opf/openproject` **`v17.8.0`** (matches the `stable/17`
bundle in use; the hocuspocus image there is pinned `17.8.0`). Re-check
against the live pilot's exact version in T1.L — `stable/17` moves.

Working assumption from the task (Rails runner inside `web`) is
**confirmed with one correction**: there is no `rails` binary magic needed —
the `web` service runs the full Rails codebase (`./docker/prod/web`), so
`docker compose exec -T web bundle exec rails runner /path/script.rb`
executes with the app's gems, DB config and environment. File transfer via
`docker compose cp`. Exact `exec`/`cp` flags against our override to be
proven live in T1.L (T1.6 covers this).
Evidence: upstream `docker-compose.yml` (`web` service, `command:
"./docker/prod/web"`); upstream README documents the same compose layout,
loopback `PORT`, override best practice and `admin`/`admin` first login.
